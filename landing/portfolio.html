We're the builders of rvo (react-vite-optimizer) — a CLI for React modernization: performance codemods, dependency upgrades, cross-framework migration, and microfrontend conversion. The tools

🔍rvo assess

Cross-framework migration readiness. Blockers flagged up front, 107-library equivalence map, go/no-go verdict.

rvo assess ./my-app --to vue

free

🗺️rvo plan

Migration architecture blueprint generated from the assessment — target structure, module order, library replacements.

rvo plan ./my-app --to vue

licensed

🔀rvo migrate

The conversion. Vue SFCs / Angular signals out, TODO(human) markers wherever judgment is needed. Source never touched.

rvo migrate ./my-app --to vue --out ./vue-app

licensed

🧩rvo split

Microfrontend readiness analysis. Feature clusters, coupling matrix, and an honest verdict: not needed / worth considering / recommended.

rvo split ./my-app

free

📦rvo split convert

Module Federation monorepo generated from your approved plan — remotes, shell, shared modules wired up.

rvo split convert --plan split-plan.json --out ./microfrontends

licensed

2. rvo split — microfrontend analysis on a demo app. Verdict: RECOMMENDED, with coupling risks called out before any split.

rvo split — microfrontend analysis
  /home/hatch/workspace/react-vite-optimizer/test/fixtures/split-demo

  Verdict: RECOMMENDED
    · 3 independently-routable feature areas with low coupling (8% cross-feature imports) — strong microfrontend candidates.
    · Shared state (ShopContext) is used by account, shop — keep it in the shell or a shared federation module.

  Feature candidates (3):
    ● account — 9 files, 328 LOC — routes: /account, /account/*
    ● admin — 8 files, 339 LOC — routes: /admin/*
    ● shop — 13 files, 457 LOC — routes: /shop/*

  Coupling — cross-feature imports: 3 (8% of feature imports; 33 intra-feature)
    ✗ admin → shop — 3 imports (risk: high)
        src/admin/AdminPanel.jsx → src/shop/ProductCard.jsx
        src/admin/AdminPanel.jsx → src/shop/shopApi.js
        src/admin/UserTable.jsx → src/shop/useCart.js

  Shared surface (keep in shell / shared modules):
    dirs: components (7 files), hooks (3 files), utils (2 files), context (1 files)
    state: ShopContext (src/context/ShopContext.jsx) — used by account, shop
    state libs: zustand

  Recommendations:
    remotes: shop, account, admin
    shell keeps: app shell, router, auth, design system
    shared via federation: react, react-dom, react-router-dom, zustand

  Risks:
    ! Decouple "admin → shop" (3 cross-imports, risk: high) before extracting — move the shared code into the shell or a shared module first.

  Next steps:
    rvo split --json --output split-plan.json   # review & edit the plan
    rvo split convert --plan split-plan.json --out ./microfrontends   # license required

🤝Uncertain parts are marked, not guessed

The converter writes TODO(human) markers wherever a transform needs judgment — idiom differences, ambiguous state, framework-specific APIs. We'd rather flag it than fake it.

🙅Honest verdicts, including "don't"

The split analyzer says not needed when your app doesn't warrant microfrontends. We'd rather talk you out of a migration than sell you a bad one.

How we work

1️⃣Assess — free

We run rvo assess / rvo split on your codebase. You get a written report: inventory, blockers, complexity, and an honest verdict.

2️⃣Plan

The assessment becomes an architecture blueprint: target structure, migration order, replacements for blocked libraries, effort estimate.

3️⃣You approve

Nothing changes until you sign off on the plan. Review it, edit it, ask questions. The plan is the contract.

4️⃣Convert

Licensed execution: detect → plan → transform → verify. Output lands in a fresh directory — your source files are never modified in place.
